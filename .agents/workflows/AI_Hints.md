# 项目开发环境与坑点指南

这个文档是为了给后续的 AI (包括不同对话或不同形态的 Agent) 以及开发者提供在这个代码库里工作时的“避坑指南”。

## 1. 虚拟环境与包管理 (uv)

本项目使用了 [uv](https://github.com/astral-sh/uv) 作为包管理和依赖管理工具。
**坑点**：如果 AI 尝试直接使用 `python -c` 或者 `pip install` 可能会因为不在虚拟环境中而报错 `ModuleNotFoundError` (例如提示找不到 `uiautomator2` )。

**正确姿势**：
所有涉及到运行 Python 脚本或者测试代码库内模块的命令，都应该加上 `uv run` 前缀。
- 错误示例: `python -c "from SearchResult import SearchResult... "`
- **正确示例**: `uv run python -c "from SearchResult import SearchResult... "`

添加新依赖时，请使用 `uv add <package>` 而不是 `pip install`。

## 2. 万词王模式与题数解析

题库原版是应对普通的 `X/Y` 形式（例如 `8/100`），但是在“万词王模式”下，题目的标记变成了 `第X关`。

**坑点**：
这不仅影响到识别 `万词王模式` 的状态获取，还会影响 `getPosition` 判断从前获取还是从后获取（需要用到数字比大小）。
如果 `getPosition` 没能提取出有效数字，抛出 `ValueError`，它会退化为返回 `1` (提取排在前面的，还没被 UI 回收的“上一题残影”)。这会导致在后续读取题目文本和选项时发生时空错位（读取了上一题的英文，确读到了本题的中文选项），导致 `相似度为 0` 并报错宕机。

**正确姿势**：
`getPosition` 已经通过正则表达式 `r'\d+'` 兼容了获取 `第X关` 里的纯数字了。后续在涉及到读取任何 Android 界面上的 `数字文本` 时，一定要注意这种包含文字的 Edge Case。

## 3. 英语单词字符过滤提取

在类似 `__englishToChinese` 这些通过 `UIAutomator2` 获取 `TextView` 内容的方法里，由于安卓渲染或者屏幕宽度的原因，获取到的 `text` 属性可能会把下一行的音标混合在一起。

**坑点**：
之前通过切分 `\n` 是不够的。如果 AI 尝试加一层纯英文字母正则 `r'^[a-zA-Z\s\-]+'` 去除音标，会引发新的灾难：形如 `colo(u)ring`、`p.m.`、`one's` 这类本身就带有标点符号的合法单词会被砍断（比如被砍成 `colo`），从而在 `Data/` 目录的本地题库里彻底失踪。

**正确姿势**：
目前的单词提取净化正则为：
```python
match = re.match(r"^[a-zA-Z\s\-\(\)\.\']+", word)
```
后来的 AI 朋友们，如果遇到新的罕见词崩溃（比如带有数字或者是 `&` 的短语），请酌情在此白名单 `r"..."` 中加壳，确保提取到原汁原味的查询关键词，但同时不要把连带的中文字符或者括号里的音标吞进去。

## 4. 特殊符号全角与半角问题

原数据库存储的中文意思与界面上显示的选项，在括号和标点符号上有时存在全角/半角 (`()` 与 `（）`) 混用的情况。

**坑点**：
使用 `in` 操作符直接比对原文本可能会因为 `多个 (人) 的` 与 `多个（人）的` 判断失败。

**正确姿势**：
题库和代码在匹配时，如果直接比对失败，需要将其投入到兜底逻辑：调用 `self.reSaveChinese(text)` 方法，它通过匹配 `[\u4e00-\u9fa5]+` 把文本脱水到只剩纯汉字，再通过 `difflib.SequenceMatcher` 求相似度。如果你在修改匹配逻辑，请保持对中文字符的脱水清洗。

## 5. 英译汉直接匹配的双向 `in` 检查

题库存储的答案有时比界面上的选项文字更短。例如题库存的是 `'B. 决定；决心'`，但界面上选项 A 的文字是 `'决定；决心；果断'`（选项顺序每次随机打乱）。

**坑点**：
如果只做单向 `choice_text in clean_result` 检查，在题库答案比选项短时会失败（`'决定；决心；果断' in '决定；决心'` → False）。这导致直接匹配跳过，落入相似度匹配，而相似度因单个义项（如 `'决定'` 2字）与完整选项（`'决定决心果断'` 6字）的 `quick_ratio` 恰好等于 0.5，又被 `> 0.5` 的严格阈值卡掉。

**正确姿势**：
匹配时使用**双向** `in` 检查：`choice_text in clean_result or clean_result in choice_text`。同时相似度阈值改为 `>= 0.5` 防止边界值遗漏。还增加纯汉字 `reSaveChinese` 脱水后的双向 `in` 兜底。
